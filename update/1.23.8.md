# Release 1.23.8 - Virtual Brand Notification Direction & Evaluation Logic Fix

Perbaikan bug evaluasi arah notifikasi Discord Virtual Brand (`summary_action` dan `is_open`) pada mode Brand Toggle dan Auto-Guarding di `main-vb/src/db.py`, mengeliminasi false alarm "GAGAL DIBUKA" saat brand ditutup/di-pause.

---

## Whats New

1. **Deterministic Status-Driven Brand Toggle Evaluation**:
   - Pada mode Brand Toggle (`is_brand_toggle == True`), arah notifikasi Discord (`summary_action` dan `is_open`) ditetapkan secara **100% deterministik mengikuti `applied_status` brand** (`applied_status == "ON"` ➔ `ACTION_OPEN` / DIBUKA; `applied_status == "PAUSED"` ➔ `ACTION_CLOSE` / DITUTUP).
   - Menghilangkan evaluasi `any(a in ("ACTION_OPEN", ...) for a in actions_types)` yang sebelumnya rentan menghasilkan false positive pembukaan jika terdapat sisa log aksi patroli sebelum toggle diaplikasikan.

2. **Accurate Action Majority Evaluation for Auto-Guarding**:
   - Pada mode Auto-Guarding (`is_brand_toggle == False`), penentuan arah notifikasi Discord dihitung dari perbandingan frekuensi aksi pemulihan aktual yang dieksekusi (`open_count >= close_count`), dengan fallback ke `applied_status` jika tidak ada aksi yang tercatat.

3. **Stale Action Buffer Purging on Status Apply**:
   - Saat status toggle baru diaplikasikan pada brand di `apply_all_pending_statuses` dan `apply_pending_status_if_needed`, buffer `_PENDING_BRAND_ACTIONS[brand_id]` dibersihkan secara aman di bawah mutex `_PENDING_LOCK`, menjamin eksekusi toggle baru steril dari riwayat aksi siklus sebelumnya.

4. **Expanded Notification Flush Test Suite**:
   - Menambahkan pengujian replikasi bug pada `tests/test_vb_notification_flush.py` (`test_flush_brand_toggle_paused_with_stale_open_action_sends_close_summary`) untuk memverifikasi bahwa penutupan brand dengan sisa log patroli lama tetap terkirim sebagai notifikasi `ACTION_CLOSE` (DITUTUP) dengan status 100% Berhasil.
   - Menambahkan pengujian `test_flush_guarding_mode_close_majority` untuk mode Auto-Guarding.

---

## Spesifikasi

1. **Virtual Brand Database Adapter (`main-vb/src/db.py`)**:
   - Pembersihan buffer `_PENDING_BRAND_ACTIONS.pop(str(row["id"]), None)` saat `_BRAND_TOGGLED_IDS.add(str(row["id"]))`.
   - Percabangan deterministik `if is_brand_toggle: is_open = (applied_status == "ON")` pada `flush_pending_brand_notifications`.
2. **Automated Unit Tests (`tests/test_vb_notification_flush.py`)**:
   - 7 test cases mencakup simulasi multi-portal, instant flush, brand toggle direction accuracy, dan guarding evaluation.
