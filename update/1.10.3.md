# v1.10.3

## Whats New

- Sinkronisasi otomatis dan penerapan instan status toggle Virtual Brand (VB) dari dashboard ke worker bot patroli VB.
- Penanganan transisi pending state (`requested_status` -> `applied_status`) saat awal siklus patroli dan penarikan outlet VB.
- Mount volume direktori `main-vb` dan `src` pada service `bot-vb` di `docker-compose.yml` untuk pembaruan kode tanpa interupsi.

## Spesifikasi

- `main-vb/src/db.py` mengimplementasikan fungsi `apply_all_pending_statuses(conn)` yang mentransfer `requested_status` dan `requested_pause_until` ke `applied_status` dan `pause_until` pada seluruh brand aktif.
- `main-vb/src/db.py` memanggil `apply_all_pending_statuses()` di awal `fetch_merchant_outlets_from_db()` dan di dalam `sync_expired_user_pauses()`.
- `main-vb/src/db.py` menggunakan `COALESCE(b.requested_status, b.applied_status)` dan `COALESCE(b.requested_pause_until, b.pause_until)` sebagai proteksi status efektif pada query outlet VB.
- `docker-compose.yml` menambahkan mount `./main-vb:/app/main-vb` dan `./src:/app/src` pada service `bot-vb`.

## Handling

- Mengeliminasi ketidaksesuaian status toggle di mana toggle dashboard VB diset OFF/PAUSED namun worker tetap membaca status lama ON.
- Menghilangkan status pending tak berujung pada metadata brand di dashboard admin.
- Memastikan `main-vb/src/worker.py` dan `src/core/browser.py` tetap 100% identik byte-for-byte dengan Bot-OC.
- Seluruh perbaikan hanya diterapkan pada adapter database Virtual Brand tanpa mengubah logika Bot-OC.
