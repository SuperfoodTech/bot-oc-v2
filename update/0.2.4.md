# Dokumentasi Rilis Update v0.2.4

Penambahan halaman khusus untuk proses pendaftaran mitra dan outlet baru.

**Tanggal Release**: 18 Agustus 2026  
**Jenis Update**: Minor UI/UX dan hardening frontend

## Whats New

1. **Halaman Tambah Mitra Khusus**:
   - Menambahkan route `/admin/mitra/tambah`.
   - Tombol `Tambah mitra` pada header diarahkan ke halaman tersebut.
   - Form dibagi menjadi Data Mitra, Data Outlet, dan Paket Layanan.

2. **Review Sebelum Simpan**:
   - Menampilkan ringkasan nama mitra, outlet, Store ID, paket, dan tanggal mulai.
   - Ringkasan diperbarui ketika input berubah.

3. **Validasi dan Feedback**:
   - Menggunakan validasi HTML native untuk field wajib, email, dan Store ID numerik.
   - Menampilkan state `Menyimpan...`, error inline, dan hasil sukses tanpa alert.
   - Menyediakan tombol salin untuk link dashboard yang berhasil dibuat.

4. **Responsive dan Aksesibilitas**:
   - Form dua kolom pada desktop dan satu kolom pada mobile.
   - Label terhubung ke input, heading section memiliki referensi ARIA, serta passcode memiliki kontrol tampil/sembunyi.

5. **Penghapusan Kredensial Service dari Frontend**:
   - Request pembuatan outlet tidak lagi mengirim username dan password service hardcoded dari JavaScript.
   - Backend tetap menggunakan nilai default internal melalui model request.

## Spesifikasi

| Komponen | File | Perubahan |
|---|---|---|
| Route halaman | `src/backend/main.py` | `GET /admin/mitra/tambah` dengan autentikasi admin |
| Halaman form | `src/backend/templates/admin_add_merchant.html` | Form lengkap, review, validasi, success/error state |
| Header CTA | `src/backend/templates/admin_header.html` | Link ke halaman tambah mitra |
| Styling | `src/backend/static/css/styles.css` | Layout halaman, responsive form, review card, feedback state |
| Endpoint data | `POST /api/v1/admin/outlets` | Dipanggil tanpa kredensial service dari browser |

## Handling

1. Route halaman mengarahkan pengguna yang belum login ke `/admin/login`.
2. Tombol submit dinonaktifkan sementara request berjalan dan diaktifkan kembali setelah selesai.
3. Jika API gagal, data form tetap dipertahankan agar admin dapat memperbaiki atau mencoba ulang.
4. Deploy perubahan frontend/backend menggunakan:
   ```bash
   docker compose build web
   docker compose up -d --no-deps web
   ```
