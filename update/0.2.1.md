# Dokumentasi Rilis Update v0.2.1

Refactor arsitektur Agency Churn Bot: dari **background thread di `fm-backend`** menjadi **container Docker tersendiri `fm-agency`** — standar produksi untuk isolasi penuh, monitoring mandiri, dan lifecycle independen.

---

## Whats New

1. **Container Baru `fm-agency`**:
   - Service Docker terpisah dengan `container_name: fm-agency`.
   - Dibangun dari `main-agency/Dockerfile` — identik dengan `main-bot` secara dependency stack.
   - `restart: unless-stopped` — daemon selalu hidup kembali otomatis jika crash.
   - Pantau hanya log bot ini: `docker logs fm-agency -f`.
   - Pantau resource: `docker stats fm-agency`.

2. **`main-agency/src/daemon.py` — Entry Point**:
   - Loop patrol continuous dengan interval `AGENCY_PATROL_INTERVAL` (default 300 detik / 5 menit).
   - Membaca flag `auto_force_close_enabled` dari DB setiap cycle — selalu reflect toggle terbaru.
   - Mengelola browser session (init, reuse, cleanup) sepenuhnya di dalam container ini.
   - Menerima signal `SIGTERM`/`SIGINT` untuk graceful shutdown.

3. **`main-agency/src/agency_api.py` — Internal HTTP Server (Port 8082)**:
   - HTTP server ringan (stdlib `http.server`) di port 8082, hanya di-expose ke network internal Docker (tidak ke host).
   - Endpoint:
     - `GET /health` → health check
     - `GET /status` → status patrol + cycle stats
     - `POST /force-close` → trigger manual force close satu outlet (dari `fm-backend`)

4. **`src/agency/runner.py` — Pure Functions**:
   - Threading dihapus total. Hanya berisi fungsi-fungsi pure: `_run_patrol_cycle()`, `_group_outlets_by_merchant()`, `run_agency_force_close_patrol()`.
   - Module-level vars `_patrol_lock`, `_patrol_driver`, `_patrol_running` diisi oleh `daemon.py` agar manual trigger via API server bisa reuse driver yang sama.

5. **`src/backend/main.py` — Proxy ke fm-agency**:
   - `POST /api/v1/agency/force-close-single` → proxy ke `fm-agency:8082/force-close`.
   - `GET /api/v1/agency/patrol/status` → proxy ke `fm-agency:8082/status`.
   - Endpoint `/api/v1/agency/patrol/start` dan `/stop` dihapus — lifecycle dikontrol Docker.

6. **`docker-compose.yml`**:
   - Service `agency` ditambahkan, env `AGENCY_INTERNAL_URL=http://fm-agency:8082` di `fm-backend`.
   - Port 8082 hanya `expose` (internal network), tidak `ports` (tidak ke host).

## Spesifikasi

| Container | Port Expose | Chrome Profile | Restart Policy |
|---|---|---|---|
| `fm-postgres` | 5435 (host) | — | `unless-stopped` |
| `fm-backend` | 3001 (host) | — | `always` |
| `fm-bot` | — | `chrome_profile_auto7313` | `always` |
| `fm-agency` | 8082 (internal) | `chrome_profile` | `unless-stopped` |

**Monitoring commands**:
```bash
docker logs fm-agency -f              # Log real-time patrol
docker stats fm-agency                # CPU/RAM
docker inspect fm-agency              # Detail container
curl http://localhost:8082/status     # TIDAK bisa dari host — internal only
```

**Cara monitor status dari host**:
```bash
# Via fm-backend API (dengan autentikasi admin):
curl http://localhost:3001/api/v1/agency/patrol/status
```

## Handling

1. **Rebuild hanya fm-agency** (jika ada perubahan di `src/agency/` atau `main-agency/`):
   ```bash
   docker compose build agency
   docker compose up -d --no-deps agency
   ```

2. **Rebuild fm-backend saja** (jika ada perubahan di `src/backend/`):
   ```bash
   docker compose build web
   docker compose up -d --no-deps web
   ```

3. **fm-bot tidak perlu di-rebuild** sama sekali dari update ini.
