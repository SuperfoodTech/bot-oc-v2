# Release 1.23.7 - Public Virtual Brand Dashboard Toggle UUID & Response Resilience Fix

Perbaikan bug toggle status brand pada Dashboard Publik Virtual Brand (`/brand/{slug}`) akibat type mismatch UUID `requested_by` pada database PostgreSQL serta peningkatan ketahanan parsing respons frontend.

---

## Whats New

1. **Public Brand Dashboard Toggle Database Integrity Fix**:
   - Memperbaiki query SQL `UPDATE vb_brands` pada fungsi `request_brand_status_public` di `src/backend/vb.py` dengan menetapkan `requested_by = NULL` (bukan string literal `'BRAND_DASHBOARD'`).
   - Mencegah error `psycopg.errors.InvalidTextRepresentation: invalid input syntax for type uuid: "BRAND_DASHBOARD"` saat toggle ON/PAUSE dioperasikan dari dashboard publik `/brand/{slug}`.

2. **Frontend Safe JSON Response Parsing**:
   - Menambahkan pengamanan parsing JSON (`try { json = await res.json(); } catch (_) { json = null; }`) pada fungsi `executeBrandToggle` dan `fetchBrandData` di `brand_dashboard.html`.
   - Mengeliminasi error `SyntaxError: Unexpected token 'I', "Internal S"... is not valid JSON` dan menampilkan pesan kesalahan (*toast*) yang bersih dan edukatif kepada pengguna jika server mengalami gangguan.

3. **Expanded Unit & Contract Test Suite**:
   - Menambahkan test contract `test_public_brand_toggle_contract` pada `tests/test_vb_pause_contract.py` untuk memverifikasi fungsionalitas toggle publik brand (ON dan PAUSED) secara otomatis.

---

## Spesifikasi

1. **Backend Database Module (`src/backend/vb.py`)**:
   - Query `UPDATE vb_brands` pada `request_brand_status_public` menetapkan `requested_by=NULL` yang valid dengan tipe kolom `uuid REFERENCES dashboard_accounts(id)`.
2. **Frontend Template (`src/backend/templates/brand_dashboard.html`)**:
   - `executeBrandToggle` & `fetchBrandData` menggunakan parsing JSON asinkron yang tangguh terhadap respons HTTP 5xx/4xx berformat teks polos.
3. **Automated Tests (`tests/test_vb_pause_contract.py`)**:
   - Pengujian contract endpoint `POST /api/v1/brand/{slug}/toggle` untuk mode buka (`ON`) dan tutup sementara (`PAUSED` durasi 30 menit).

---

## Handling

1. **Zero-Downtime Web Deployment**:
   - Build dan restart container web dilakukan dengan perintah `docker compose build web && docker compose up -d --no-deps web` tanpa menginterupsi bot patroli maupun database.
2. **Backward Compatibility**:
   - Tidak ada perubahan skema database PostgreSQL atau perubahan kontrak API eksternal.
